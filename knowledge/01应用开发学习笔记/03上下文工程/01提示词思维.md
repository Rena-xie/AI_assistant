### 一、从基础提示到高级推理范式的演进

#### 1. 基础提示范式

- **零样本提示（Zero-Shot）**：不给大模型提供任何示例，直接下达任务指令。表达应直接、明确、具体，说明“做什么”，而不是“不做什么”。
- **少样本提示（Few-Shot）**：在提示词中增加 1 个或多个具体的“输入 $\rightarrow$ 输出”示例，但不包含中间推理逻辑，主要用于固定严格的输出结构或统一特定的格式风格。

#### 2. 思维推理范式

- **思维链提示（CoT, Chain of Thought）**：
    - _机制_：在 Few-Shot 示例中写出详细的中间推理步骤，或在 Zero-Shot 下加入“让我们一步一步地思考”等引导语。
    - _场景_：激活模型的逻辑推理能力，适合解决复杂的计算、推演和逻辑任务。
- **自动思维链（Auto-CoT）**：
    - _机制_：包含两阶段。阶段 1（问题聚类）将给定问题划分为几个不同的聚类；阶段 2（演示抽样）从每个聚类中选择代表性问题，通过简单的启发式 Zero-Shot-CoT 自动生成推理链范例，并限制字数 and 推理步骤在 5 步左右进行过滤。
    - _场景_：解决手动编写 Few-Shot 推理步骤成本高、质量参差不齐的问题。

**思维树 (Tree of Thoughts, ToT)**

- **原理**：将问题的解空间建模为一棵树。每个节点代表一个中间思考状态（Thought）。LLM 不仅生成下一步可能，还会充当“评价器”对当前节点打分（如：`Sure / Maybe / Impossible`）。结合广度优先（BFS）或深度优先（DFS）算法，允许系统在发现死胡同时**回溯（Backtrack）并剪枝**。

- **主动提示（Active-Prompt）**：
    - _机制_：将题库给 LLM 重复解答，筛选出解答不确定性高（即最容易出错）的难题，专门交给人类写出高质的 CoT 步骤，再重新推断新问题。
    - _场景_：用在对推理准确率要求极高、预算有限且希望把人类标注成本花在刀刃上的工业级任务。

#### 3. 动态调度与自动化

- **提示链（Prompt Chaining）**：
    - _机制_：通过代码将上一个 LLM 节点的输出传给下一个节点，分步转换或处理，直到达到最终结果。
    - _场景_：如设计两个提示，提示一负责提取原始文档的引文，提示二以引文和原始文档为输入来正式回答问题。
- **方向刺激提示（DSP, Directional Stimulus Prompting）**：
    - _机制_：微调一个极轻量的小模型，针对用户输入实时生成特定的引导性线索（刺激），并将“任务 + 刺激线索”拼接打包发给闭源大模型，最后根据回答评估分数利用强化学习（RL）继续训练该小模型。
    - _场景_：在不微调、不改变闭源大模型参数的前提下，以极低成本强行约束大模型必须包含某些关键信息或风格（如病历摘要、客服流）。
- **程序辅助语言模型（PAL, Program-Aided Language Models）**： ^dc3210
    - _机制_：让大模型（LLM）仅负责理解语义，并将其翻译为包含变量定义与计算逻辑的 Python 代码，代码被发送至外部 Python 解释器直接算出结果，回填答案。
    - _场景_：针对基本数学计算、日期推算等硬逻辑，PAL 能彻底消除计算幻觉，实现 0 计算错误。
- **自动提示工程师（APE, Automatic Prompt Engineer）**：
    - _机制_：提示词的自动化调优、打分和进化
    - _代表工具_：
        - **DSPy**：通过代码定义输入输出格式，DSPy 自动在后台拼接、测试、打分并生成最优 Prompt。
        - **Promptfoo**：提示词自动化测试（Evals）的命令行工具，支持多 Prompt 批量在测试集上跑分生成对比图表，快速选出表现最优的 Prompt。

#### 二、高推理优化范式对比

| 优化范式     | **思维链 (CoT)**   | **主动提示 (Active-Prompt)**        | **程序辅助模型 (PAL)**                      | **自动提示工程师 (APE)**                       |
| :------- | :-------------- | :------------------------------ | :------------------------------------ | :-------------------------------------- |
| **核心机理** | 示例中包含详细的中间推理步骤。 | 跑题库测试，筛选出高不确定性错题，专由人类标注 CoT 步骤。 | 将自然语言翻译为 Python 代码，并脱离 LLM 交由外部解释器执行。 | 算法自动拼接 Few-Shot、运行测试、计算评估分并反向迭代 Prompt。 |
| **思考路径** | 串行自然语言逻辑推理。     | 基于易错题的精准人工介入推理。                 | 逻辑翻译与代码运行分离控制。                        | 基于测试数据集自动跑分进化。                          |
| **适用任务** | 逻辑推理、数学应用题解法。   | 预算有限、有明确标注数据集、需要极限压缩错误率的系统。     | 涉及高精度算术、统计、日期换算等硬性控制流。                | 人工调参和提示词调试成本过高、频繁发生模型漂移的场景。             |
| **落地工具** | 自然语言 Prompt 编写。 | Python 脚本进行多次运行统计。              | 结合 `exec()` 或外部沙箱环境。                  | **DSPy**（斯坦福框架）、**Promptfoo**。          |
