智能体要在生产环境中完成具体任务，必须打通大模型推理生成与本地/外部代码执行之间的闭环链路。

## Function Calling（函数调用）四步流转机制

在实际开发中，大模型调用外部工具的物理链路遵循以下标准流程：

* **工具注册**：在向大模型发送请求时，在参数中注入使用 JSON Schema 描述的工具列表（明确定义函数名、入参数据类型、用途描述及何时调用）。使用标准的 JSON Schema 描述函数名、入参类型与函数用途。
* **意图识别与参数提取**：LLM 判定需要调用工具，主动暂停普通自然语言文本的生成，转而输出一段符合 JSON Schema 规范的标准化调用指令（例如：`{"name": "query_db", "args": {"user_id": 1024}}`）。
* **外部执行（Engine Runtime）**：Python 后端或沙箱环境捕获该 JSON 结构，提取参数并在本地或通过 API 运行真实的程序逻辑，执行真实的数据库查询或外部 API 接口请求。
* **结果回填（Observation）**：将工具运行返回的真实结果（Observation）包装在对话上下文中重新投喂给大模型，由其二次整合后决定输出最终回答或触发下一步工具调用，输出最终的自然语言。

## 自定义工具与 MCP 协议

* **自定义工具注册**：这是 AI 应用开发最核心的定制环节。在 FastAPI / LangGraph 等纯代码开发中，直接将普通 Python 业务函数加上框架装饰器，即可一键注册为 Agent 工具；在 Dify 等平台，支持直接粘贴 Python 代码块或按 OpenAPI/Swagger 规范注册外部 API 服务。
* **MCP 协议（Model Context Protocol）**：成为行业公认的统一工具调用与上下文共享新标准，标准化了 Agent 与本地开发工具链、数据库、IDE（如 Cursor）之间的连接协议。
**什么是 MCP（Model Context Protocol）？**

**MCP（模型上下文协议）** 是由 Anthropic 提出并开源的**标准化通信协议**。它的核心目标是解决“LLM/Agent 应用程序如何统一、安全地连接外部数据源与工具”的问题。

在 MCP 出现之前，如果想让 Agent 调用 GitHub、连接 PostgreSQL 数据库或读取本地文件，开发者必须为每一个平台或框架编写定制化的适配接口（即 N×M 的重复接入难题）。MCP 的作用类似于 AI 领域的 **“USB-C 接口”**，只要遵循这一协议，任何工具都可以无缝插接到任何大模型应用中。

**MCP 的核心架构**

MCP 采用标准的 **客户端 - 服务端（Client-Server）** 架构：

- **MCP Host（宿主应用）**：发起 AI 对话或决策的大型应用程序，如 Claude Desktop、Cursor 编辑器或开发者构建的 Agent 系统。
    
- **MCP Client（客户端）**：运行在 Host 内部的协议客户端，负责管理与各个 MCP Server 的连接与交互。
    
- **MCP Server（服务端）**：独立运行的轻量级程序，专门暴露特定的数据或操作能力（如 `mcp-server-github`、`mcp-server-postgres`、`mcp-server-filesystem`）。
    

**MCP 提供的三种通用能力（Primitives）**

- **Tools（工具）**：可被模型调用的函数（如“创建 GitHub Issue”、“执行 SQL 查询”），调用由 MCP Server 物理执行并返回结果。
    
- **Resources（资源）**：向模型暴露的上下文数据（如本地文件内容、数据库表结构、日志文件），类似于 API 的只读 GET 接口。
    
- **Prompts（提示词模板）**：由 MCP Server 预设的标准 Prompt 模版，方便用户在 Host 中快速触发特定的工具链工作流。
    

**核心优势**

- **安全与隔离**：MCP Server 可以运行在独立的沙盒或本地受控环境中。敏感的 API 密钥和数据库密码只保存在本地 MCP Server 中，云端大模型只能看到工具的输入输出，无法直接接触密钥。
    
- **一次编写，随处复用**：开发者只需编写一个 `mcp-server-mysql`，无论是 Claude Desktop、Cursor 还是自研的 LangChain 应用，只要支持 MCP 协议，就能直接挂载并调用该数据库。
    
- **本地与云端无缝打通**：大模型无需将大量本地文件上传到云端，而是通过 MCP 按需向本地 Server 请求具体的资源片段。
## 自动推理并使用工具 (ART 范式)

ART 是一种能够极大提升智能体工具调度合理性的经典范式。其核心工作原理如下：

* **多步示范匹配**：当接到一个新任务的时候，系统自动从任务库中选择多步推理和使用工具的示范。
* **暂停与恢复生成**：在测试与实际执行中，当需要调用外部工具时，模型会先暂停文本生成；待宿主程序完成工具调用并将输出结果整合后，再将结果喂回，继续接着往下生成。
