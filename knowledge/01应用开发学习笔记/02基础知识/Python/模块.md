### 一、 核心知识点与语法

#### 1. 模块（Module）与包（Package）的组织关系

- **模块（Module）**：在 Python 中，**一个 `.py` 文件就是一个模块**。模块名就是文件名（不含 `.py` 后缀）。优点是避免函数名/变量名冲突。
    
- **包（Package）**：按目录组织模块的方式，解决模块名冲突问题。
    
- **`__init__.py` 的作用**：
    
    - 任何一个包含 `__init__.py` 文件的文件夹都会被 Python 识别为一个包。
        
    - `__init__.py` 可以是空文件，也可以在其中定义包的初始化代码，或者通过 `__all__` 暴露包的核心接口。


```
my_ai_project/              # 项目根目录
│── main.py                 # 入口模块
└── rag_engine/             # 包 (Package)
    ├── __init__.py         # 标识 rag_engine 为包，并可导出模块
    ├── loader.py           # 模块 (Module): rag_engine.loader
    └── retriever.py        # 模块 (Module): rag_engine.retriever
```

#### 2. `import` 语句的多种导入方式

- **标准导入**：`import rag_engine.loader`（使用时需带完整前缀：`rag_engine.loader.load_doc()`）。
    
- **精准导入**：`from rag_engine.loader import load_doc`（可以直接调用 `load_doc()`）。
    
- **别名导入**：`import pandas as pd` / `import numpy as np`（简化长模块名的调用）。

#### 3. 变量/函数作用域与命名约定（隐私保护）

- **公开（Public）**：正常的变量和函数名，如 `name`、`predict()`，可被任何模块直接调用。
    
- **私有（Private）**：以单下划线 `_` 或双下划线 `__` 开头，如 `_config`、`__internal_calc()`。
    
- **约定俗成**：Python 语法没有严格限制私有属性的访问，但**按规范不应该从模块外部直接引用私有变量/函数**。它们通常用于模块内部的抽象封装。
    
- **特殊变量（Special）**：形如 `__name__`、`__doc__`、`__file__`，是 Python 内置的元数据变量。

#### 4. 黄金机制：`if __name__ == '__main__':`

- **原理**：
    
    - 当 `.py` 文件被**直接运行**时，Python 解释器会将 `__name__` 变量设为 `'__main__'`。
        
    - 当该文件被**作为模块导入**（`import`）到其他文件时，`__name__` 的值为当前模块的名字（如 `'rag_engine.loader'`）。
        
- **用途**：编写模块的**单元测试代码**或 **CLI 命令行入口**，确保被其他模块 `import` 时不会误触发测试逻辑。
    

```
# rag_engine/loader.py

def load_pdf(filepath: str):
    return f"加载 PDF 内容: {filepath}"

def _parse_raw_bytes(data: bytes):
    """私有辅助函数，不建议外部直接调用"""
    pass

# 只有直接运行当前文件时，以下测试代码才会执行
if __name__ == '__main__':
    print("正在对 loader.py 进行单元测试...")
    res = load_pdf("test.pdf")
    print(res)
```

#### 场景 2：解析命令行参数与环境变量（命令行 AI 工具开发）

内置模块 `sys` 的常用操作：获取命令行传入的 Prompt 参数或系统环境：

Python

```
import sys

def main():
    # sys.argv 包含了命令行传入的参数列表
    # sys.argv[0] 是脚本文件名，sys.argv[1] 是第一个参数
    if len(sys.argv) < 2:
        print("用法: python ai_cli.py \"你的 Prompt\"")
        sys.exit(1)
    
    user_prompt = sys.argv[1]
    print(f"🤖 正在向 AI 发送请求: {user_prompt}")

if __name__ == '__main__':
    main()
```

### 一、 核心知识点与语法

#### 1. 包管理工具 `pip` 与 PyPI 官方仓库

- **什么是 PyPI**：PyPI（Python Package Index）是 Python 官方的第三方开源代码仓库，包含了数以百万计的第三方库。
    
- **`pip` 的常用核心命令**：
    
    - **安装模块**：`pip install <package_name>`（如 `pip install requests`）
        
    - **指定版本安装**：`pip install <package_name>==1.2.0`
        
    - **升级模块**：`pip install --upgrade <package_name>`
        
    - **卸载模块**：`pip install -un <package_name>` 或者 `pip uninstall <package_name>`
        
    - **查看已安装模块**：`pip list`
        
    - **查看特定模块信息**：`pip show <package_name>`
        

#### 2. 国内镜像源加速（解决下载慢/超时问题）

由于官方 PyPI 服务器位于海外，直接下载较大的 AI 依赖包（如 Torch、TensorFlow）极易出现 `ReadTimeoutError` 网络超时。

- **临时使用国内镜像**：
    
    Bash
    
    ```
    pip install openai -i https://pypi.tuna.tsinghua.edu.cn/simple
    ```
    
- **永久配置国内镜像源（推荐）**：
    
    Bash
    
    ```
    pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
    ```
    

#### 3. 生产级依赖管理：`requirements.txt`

在团队协作或部署 AI 项目到云端服务器时，必须通过 `requirements.txt` 统一项目依赖库的版本：

- **导出当前环境依赖**：
    
    Bash
    
    ```
    pip freeze > requirements.txt
    ```
    
- **一键批量安装依赖**：
    
    Bash
    
    ```
    pip install -r requirements.txt
    ```
    

#### 4. 解决包冲突的关键：虚拟环境（Virtual Environment）

- **痛点**：项目 A 依赖 `langchain==0.0.300`，而项目 B 依赖 `langchain==0.1.0`。如果都安装在全局 Python 环境中，就会产生**版本冲突（Dependency Hell）**。
    
- **解决方案**：使用 `venv`（Python 内置）或 `conda` 为每个项目创建**独立的沙盒环境**。
    
    Bash
    
    ```
    # 1. 在项目根目录创建名为 venv 的虚拟环境
    python -m venv venv
    
    # 2. 激活虚拟环境
    # Windows 平台:
    venv\Scripts\activate
    # macOS / Linux 平台:
    source venv/bin/activate
    
    # 3. 退出虚拟环境
    deactivate
    ```

#### 场景 3：Docker 容器化部署中的依赖构建（`Dockerfile`）

在将 AI 智能体应用部署到 Docker 或 Serverless 云平台时，标准的文件组织包含 `requirements.txt`：

Dockerfile

```
# 示例 Dockerfile 片段
FROM python:3.10-slim

WORKDIR /app

# 优先复制 requirements.txt 充分利用 Docker 缓存
COPY requirements.txt .

# 镜像加速安装第三方模块
RUN pip install --no-cache-dir -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

COPY . .

CMD ["python", "main.py"]
```
