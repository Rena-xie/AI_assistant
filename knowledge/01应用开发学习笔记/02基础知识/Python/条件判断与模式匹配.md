
> `if-elif-else` 是"条件判断"；`match-case` 是"模式匹配"。

## 一、条件判断：if - elif - else

### 1. 结构与执行顺序

**语法规范：**

```python
if 条件1:
    执行语句1
elif 条件2:
    执行语句2
else:
    执行语句3
```

**核心机制（短路逻辑）**：条件判断是从上往下执行的。一旦某个 `if` 或 `elif` 的条件满足，执行完对应的语句后，后续所有的 `elif` 和 `else` 都会被直接跳过，不再进行判断。

### 2. 条件表达与隐式布尔值转换

- **组合条件**：使用 `and`（与）、`or`（或）、`not`（非）进行多条件组合。
- **非空判断（非常重要）**：Python 中，以下值在条件判断中都会被视作 `False`：
    - 数字：`0`、`0.0`
    - 空序列/容器：`""`（空字符串）、`[]`（空列表）、`()`（空元组）、`{}`（空字典）
    - 空对象：`None`

### 3. AI 开发场景

在 AI 应用开发中，我们不会让大模型处理所有事情，而是需要通过 `if-else` 对流程进行精准把控与分流。

#### 场景 1：AI Agent 意图识别与路由分发

利用轻量级模型或逻辑判断用户的意图，从而决定调用哪个工具或 Prompt：

```python
user_intent = classify_intent(user_query)  # 假设返回 "search", "code", 或 "chat"

if user_intent == "search":
    # 路由到联网搜索工具
    response = run_web_search(user_query)
elif user_intent == "code":
    # 路由到代码生成专属 Prompt
    response = run_code_agent(user_query)
else:
    # 默认调用基础大模型对话
    response = call_llm(user_query)
```

#### 场景 2：Guardrails（AI 安全防护栏与非空校验）

在把数据发送给大模型 API 之前，或者在大模型吐出结果之后，必须使用 `if` 进行校验，防止空指针异常或敏感违规：

```python
# 1. 检查输入是否有效（利用非空判断）
if not user_input.strip():
    print("错误：用户输入不能为空！")

# 2. 检查大模型 API 返回结果是否有效
response = call_llm_api(prompt)

if response is None or not response.get("content"):
    print("大模型未返回内容或响应超时，启用降级方案。")
else:
    print("AI 输出：", response["content"])
```

#### 场景 3：大模型 API 速率限制（Rate Limit）与模型分流

根据 Token 数量决定是走快速模型还是高精度模型：

```python
prompt_tokens = count_tokens(prompt)

# 根据 Token 长度选择模型，节省成本与响应时间
if prompt_tokens > 8000:
    model_name = "gpt-4o-mini"  # 支持长上下文且便宜的模型
else:
    model_name = "gpt-4o"

response = call_model(model_name, prompt)
```

## 二、模式匹配：match-case

> 注：`match-case` 是 Python 3.10 引入的新特性（原文未直接说明，供参考）。

### 1. 基础匹配（替代繁琐的 if-elif）

**语法规范：**

```python
match score:
    case 'A':
        print('优秀')
    case 'B':
        print('良好')
    case _:  # 通配符 _ 相当于 else，用于匹配其他所有情况
        print('其他')
```

示例：

```python
role = "admin"

match role:
    case "admin":
        print("管理员")
    case "user":
        print("普通用户")
    case "guest":
        print("游客")
    case _:
        print("未知角色")
```

- **组合匹配（或操作）**：使用 `|` 分隔多个选项，例如 `case 'A' | 'B':`。

### 2. 结构化匹配（AI 开发中的杀手锏）

`match-case` 不仅能比对数值，还能解构复杂的数据结构（列表、元组、字典）：

**匹配列表/元组**：可以直接解构出列表中的元素和剩余部分。

```python
match args:
    case ['search', query]:          # 匹配只有两个元素的列表，且第一个是 'search'
        print(f"搜索: {query}")
    case ['code', lang, *code_body]: # 使用 * 匹配剩余的所有元素
        print(f"执行 {lang} 代码")
```

**匹配字典**：能够精准提取字典中的键值对（非常适合解析大模型返回的 JSON）。

### 3. 卫语句（guard clause）

在 `case` 后面加上 `if` 条件判断，只有表达式成立才算匹配成功：

```python
match command:
    case ['run', script] if script.endswith('.py'):
        print("运行 Python 脚本")
```

### 4. AI 开发场景

在 AI 应用开发中，大模型的输出通常是结构化的 JSON，或者我们需要让 Agent 根据大模型的指令去调用不同的外部工具，`match-case` 是处理这类结构化路由的最佳方式。

#### 场景 1：AI Agent 工具调用

大模型在决定调用工具时，会返回工具名称和参数，用 `match-case` 进行分发极其清晰：

```python
tool_call = {"name": "get_weather", "args": {"city": "Beijing"}}

match tool_call:
    # 精准匹配工具名称，并解构出 args 中的具体字段
    case {"name": "get_weather", "args": {"city": city_name}}:
        response = fetch_weather_api(city_name)

    case {"name": "search_database", "args": {"query": query, "top_k": k}}:
        response = vector_db_search(query, top_k=k)

    case {"name": name}:
        response = f"未知的工具名称: {name}"

    case _:
        response = "格式错误的工具调用指令"
```

#### 场景 2：解析大模型多轮/流式的结构化响应

在处理 Agent 步进吐出的中间状态事件流时：

```python
# 假设处理 Agent 步进吐出的事件消息
event = ["THINKING", "正在思考如何解答..."]

match event:
    case ["THINKING", content]:
        print(f"🤔 AI 思考中: {content}")

    case ["TOOL_USE", tool_name, input_data]:
        print(f"🛠️ 调用工具 {tool_name}，参数: {input_data}")

    case ["FINAL_ANSWER", answer]:
        print(f"✅ 最终回答: {answer}")

    case _:
        print("未知事件类型")
```

#### 场景 3：命令解析与 Prompt 路由

在编写 AI 命令行工具或企微/Slack 机器人时，解析用户的快捷指令：

```python
command_input = user_input.split()

match command_input:
    case ["/clear"]:
        reset_chat_history()
    case ["/model", model_name]:
        switch_llm_model(model_name)
    case ["/system", *system_prompt]:
        update_system_prompt(" ".join(system_prompt))
    case _:
        send_to_llm(user_input)
```

## 三、循环

循环控制是处理批量文本、数据切片（Chunking）、流式响应（Streaming）以及 Agent 多轮决策的核心工具。

### 1. for...in 循环（最常用）

用于遍历可迭代对象（如 `list`、`tuple`、`dict`、`str`）：

```python
names = ['Alice', 'Bob', 'Charlie']
for name in names:
    print(name)
```

**`range()` 函数**：生成连续整数序列，常配合 `for` 做固定次数的迭代。

```python
# range(5) 生成 0, 1, 2, 3, 4
for i in range(5):
    print(f"第 {i+1} 次尝试")
```

### 2. while 循环

只要条件为 `True` 就一直循环，直到条件变为 `False`：

```python
count = 0
while count < 3:
    print(count)
    count += 1
```

### 3. break 与 continue 控制

- **`break`**：直接打断并跳出整个循环。
- **`continue`**：跳过当前这一轮剩余的代码，直接进入下一轮循环。
- **避坑提醒**：不要滥用 `break` 和 `continue`，它们会让流程控制变复杂。但在 AI 场景中，处理 API 异常重试或流式截断时经常需要配合 `if` 使用。

### 4. AI 开发场景

在 AI 应用开发中，数据大多以集合或流的形式流动，循环是处理这些数据的核心。

#### 场景 1：大模型流式输出处理（Streaming Response）

当调用 OpenAI 或 Claude 的 API 开启 `stream=True` 时，大模型会像打字机一样一字一字吐出数据。需要用 `for` 循环实时读取并拼装回答：

```python
# 假设 response 是大模型吐出的流式生成器
response = call_llm_stream("请写一篇关于AI的短文")

full_answer = ""
for chunk in response:
    # 提取当前吐出的增量文本
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)  # 实时刷在屏幕上
        full_answer += content
```

#### 场景 2：RAG（检索增强生成）中的批量文档向量化与切片

在构建向量数据库时，你可能有几百个 Markdown 文件或 PDF 页面，需要批量调用 Embedding API 转成向量存库：

```python
documents = ["段落1...", "段落2...", "段落3..."]
embedded_docs = []

for doc in documents:
    # 逐个调用向量模型 API
    vector = get_embedding(doc)
    embedded_docs.append({"content": doc, "vector": vector})
```

#### 场景 3：AI Agent 自动决策与重试循环（ReAct Loop & Retry）

Agent 在执行任务时（例如：搜索网络、调用 API），可能需要经过多轮思考与工具调用，或者在网络报错时进行自动重试：

```python
max_retries = 3
retry_count = 0

# 使用 while 循环进行 API 失败重试
while retry_count < max_retries:
    try:
        response = call_unstable_ai_api(prompt)
        print("调用成功！")
        break  # 成功后跳出重试循环
    except Exception as e:
        retry_count += 1
        print(f"调用失败，正在进行第 {retry_count} 次重试...")
        if retry_count == max_retries:
            print("达到最大重试次数，任务失败。")
```

## 附：if-elif-else 与 match-case 的选择（注：本节为归纳总结，原文未直接给出）

- `if-elif-else`：通用条件判断，适合区间判断、复杂布尔逻辑组合（`and`/`or`/`not`）。
- `match-case`：更适合"结构化匹配"——尤其是解构列表/元组/字典，比如解析大模型返回的 JSON 或工具调用指令；分支较多且基于数据结构形态时，可读性优于 `if-elif`。
- 两者不是互斥关系，可以在同一个 Agent 系统中配合使用：`if` 做前置校验（Guardrails），`match-case` 做结构化的工具路由分发。
