###  一、调用函数
#### 1、核心语法与规则

1. **基本语法与使用规则**
	- **语法** ： `函数名(参数1, 参数2, ...)`
		- **参数个数与类型检查** ：调用函数时传入的 **参数个数** 或 **参数类型** 与定义不符时，Python 会抛出 `TypeError` 。
2. **核心内置函数及其常用用途**
	- **数据类型转换函数** ：
		- `int('123')` / `float('12.34')` ：把其他类型转为整数或浮点数。
		- `str(123)` / `bool(1)` ：把其他类型转为字符串或布尔值（0/空为 `False` ，其余为 `True` ）。
		- **数学与数值处理** ：
		- `abs(-20)` ：求绝对值。
		- `max(1, 2, 5, 3)` / `min(...)` ：返回多个参数或可迭代对象中的最大/最小值。
		- **序列转换与生成** ：
		- `hex(255)` ：将整数转为十六进制字符串（如 `'0xff'` ）。
3. **函数名本质（重要概念）**
	- 在 Python 中， **函数名其实就是指向一个函数对象的引用/变量** 。
		- 意味着你可以把函数名赋给另一个变量，例如：
		```
		a = abs  # 变量 a 此时也指向了 abs 函数
		print(a(-10))  # 输出 10
		```

#### 2、开发场景

在大模型调用、Agent 架构中， **“调用函数”** 几乎贯穿始终：

1. **数据类型强制转换与清洗（API 入参/出参处理）**
	- 大模型吐出的数据往往是字符串类型，在解析前需要使用 `int()` 、 `float()` 等函数将数据规范化：
		```
		user_input = "5"  # 从网页前端传来的字符串
		max_tokens = int(user_input)  # 转换为整数以符合 LLM API 的入参规范
		```
2. **工具调用 / 函数调用
	- 在构建 AI Agent 时，大模型并不能直接操作数据库或访问网页，而是通过输出结构化 JSON，指示程序 **去“调用某个特定的 Python 函数”** 。
	- 你需要理解函数名作为引用的概念，以便动态映射和执行工具函数：
		```
		# 映射工具字典
		tools = {
		    "get_weather": get_weather_func,
		    "calculator": calculate_func
		}
		# 大模型指定要调用的函数名称
		action_name = "get_weather"
		# 动态调用对应函数
		result = tools[action_name](location="Tokyo")
		```

### 二、 定义函数
 
 LLM 工具调用、Prompt 构建、LangChain/LlamaIndex 自定义节点中的关键实践。

#### 1\. 基础定义语法 (def 与 return)

- **语法结构** ：
	```
	def my_function(param1, param2):
	    # 函数体
	    return result
	```
- **返回值机制** ：
	- 执行到 `return` 时函数立刻结束。
	- 若没有 `return` 或只写 `return` ，默认返回 `None` 。

#### 2\. 空函数与 pass 占位符

- 在还没设计好代码实现时，可以用 `pass` 保证语法合法不报错：
	```
	def process_user_query(query):
	    pass  # 待后续接入大模型逻辑
	```

#### 3\. 参数检查

- Python 不会在定义时强制限制参数类型，但在重要流程中，可以使用 `isinstance(x, (int, float))` 进行校验，如果不符合则用 `raise TypeError('错误提示')` 主动抛出异常。

#### 4\. 返回多个值

- **多返回值语法** ：
	```
	def get_coordinates():
	    return 10, 20  # 自动封装为元组 (10, 20)
	x, y = get_coordinates()  # 自动解包赋值
	```
- **本质** ：Python 并不是真的返回了多个值，而是返回了一个 `tuple` （元组），利用变量解包实现了“多返回值”的效果。

#### 5.开发场景

自定义函数是构建 AI Agent、RAG 流水线以及封装 LLM 调用的基础单元。

#### 场景 1：封装 AI 工具函数

在 Agent 架构中，大模型通过选择我们定义的函数来与外部现实世界交互。定义一个清晰的工具函数是极度常见的需求：


在 RAG（检索增强生成）流程中，自定义函数常用于处理检索到的文档，同时返回处理后的上下文文本和元数据（如匹配度评分）：

```
    avg_score = sum([doc["score"] for doc in raw_docs]) / len(raw_docs)
    
    # 返回多个值（上下文内容 + 统计评分）

# 使用多值解包接收
```

在处理 LLM 输出的 JSON 或提取关键信息时，如果 AI 没有输出期望格式，可以结合 `pass` 和逻辑兜底：

### 三、函数的参数
 LangChain、LlamaIndex 框架调用，LLM API 参数传递，自定义工具/Agent 中使用最频繁的技术点。

#### 1\. 位置参数与默认参数

- **位置参数** ：按顺序传递，必填。
- **默认参数** ：简化函数调用，必选参数在前，默认参数在后。
- **重大避坑** ： **默认参数必须指向不可变对象！**
	- ❌ **错误** ： `def add_item(item, L=[])` （多次调用会导致列表累加，产生逻辑 Bug）。
	- ✅ **正确** ： `def add_item(item, L=None): if L is None: L = []` 。

#### 2\. 可变参数 (args)

- 用于接收 **任意数量的位置参数** ，在函数内部自动组装为一个 **`tuple` （元组）** 。
	```
	def calc(*numbers):
	    return sum(numbers)
	calc(1, 2, 3)  # numbers 接收为 (1, 2, 3)
	```

#### 3\. 关键字参数 (kw)

- 用于接收 **任意数量的键值对** ，在函数内部自动组装为一个 **`dict` （字典）** 。
	```
	def build_user(name, **kw):
	    print(name, kw)
	build_user("Alice", age=25, city="Beijing")  # kw 接收为 {'age': 25, 'city': 'Beijing'}
	```

#### 4\. 命名关键字参数

- 用于 **限制调用者只能传入指定的关键字参数** 。用 `*` 作为分隔符。
	```
	def person(name, *, city, job):  # 限制必须显式传入 city 和 job
	    print(name, city, job)
	person("Jack", city="Beijing", job="Engineer")
	```

#### 5\. 参数解包与万能调用 (\* 与 \*\*)

- **解包传入** ：可以用 `*list` 将列表解包为可变参数，用 `**dict` 将字典解包为关键字参数。
- **万能签名** ： `func(*args, **kw)` 可以接收任意形式的参数调用。

#### 6. 开发中场景

在 AI 开源框架（如 OpenAI SDK、LangChain、LlamaIndex）中，参数解包与关键字参数几乎无处不在。

#### 场景 1：动态透传 LLM API 参数 (\*\*kwargs)

在封装大模型 Client 时，不同模型的参数（如 `temperature`, `top_p`, `max_tokens`, `presence_penalty` ）各不相同。通过 `kwargs` 可以优雅地支持未来任意新参数，无需修改函数定义：

```
def call_llm_api(prompt: str, model="gpt-4o", **kwargs):
    """
    通用大模型调用封装
    kwargs 可以接收包含 temperature, top_p 等任意额外的参数字典
    """
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        **kwargs  # 动态将额外的配置解包合并进来
    }
    # 发送请求逻辑...
    return payload

# 调用时灵活传递各种参数
call_llm_api("你好", temperature=0.7, top_p=0.9, stream=True)
```

#### 场景 2：AI Agent 注册工具时的参数限制（命名关键字参数）

构建 Agent 工具（Tools）时，为了确保大模型传入的参数严格符合预期，常使用命名关键字参数限制结构，避免大模型生成非法参数：

```
def search_knowledge_base(query: str, *, top_k=3, score_threshold=0.8):
    """
    定义 RAG 检索函数，强制限定 top_k 和 score_threshold 必须显式以关键字传入
    """
    print(f"搜索: {query}, 数量: {top_k}, 阈值: {score_threshold}")

# 强制要求 key=value 的调用方式
search_knowledge_base("Python 函数参数", top_k=5)
```

#### 场景 3：装饰器与切面日志记录 (\*args, \*\*kw)

在监控大模型调用的耗时或 Token 消耗时，常用的装饰器必须使用 `*args, **kw` 来包裹原始函数：

```
import time

def log_execution_time(func):
    """通用日志装饰器"""
    def wrapper(*args, **kwargs):
        start_time = time.time()
        # 万能转发参数给被调用的 AI 函数
        result = func(*args, **kwargs)
        print(f"函数 {func.__name__} 执行耗时: {time.time() - start_time:.2f}s")
        return result
    return wrapper
```

### 四、 递归函数

#### 1\. 递归的基本概念与要素
 JSON/Tree 嵌套文档解析、LangGraph/Agent 递归图推演、RAG 目录递归检索中的重要落地场景。

- **概念** ：一个函数在内部 **调用其自身** 。
- **两大必备要素** ：
	1. **递归终止条件（基线条件 / Base Case）** ：明确什么时候停止递归（例如 `n == 1` ），否则会导致死循环。
	2. **递归推导公式（递归步骤 / Recursive Step）** ：将大问题拆解为规模更小的子问题（例如 `fact(n) = n * fact(n-1)` ）。

#### 2\. 函数调用栈与栈溢出（RecursionError）

- **原理** ：计算机通过调用栈（Call Stack）保存函数的局部变量和调用信息。每多一层递归调用，栈就会增加一层栈帧。
- **栈溢出风险** ：Python 官方解释器默认限制了递归深度（一般为 1000 层）。若超过此深度，会直接抛出： `RecursionError: maximum recursion depth exceeded`

#### 3\. 尾递归及其局限性

- **尾递归（Tail Recursion）** ：在函数 `return` 语句中 **只包含对自身本身的调用** ，不包含额外的算术表达式（如 `return fact_iter(num - 1, num * product)` ）。
- **Python 局限** ： **Python 解释器没有对尾递归做优化** 。这意味着即使你改写成了尾递归格式，在 Python 中依然会报栈溢出错误（需要特别注意这一特性）。

#### 4.开发场景

在现代 AI 应用开发中，数据往往呈现 **非线性、树状或图状结构** ，递归是处理这类场景最优雅的工具。

#### 场景 1：大模型输出的 JSON / Tree 复杂数据嵌套提取

大模型（LLM）返回的 Function Calling 或结构化 JSON 常常包含嵌套树形结构（如多级分类、思维导图 Tree）。需要使用递归层层剥离：

```
def extract_all_text(node):
    """递归提取大模型生成的树形 JSON 中的所有文本内容"""
    if isinstance(node, str):
        return [node]
    
    results = []
    if isinstance(node, dict):
        for key, value in node.items():
            # 递归处理字典的 value
            results.extend(extract_all_text(value))
    elif isinstance(node, list):
        for item in node:
            # 递归处理列表的项
            results.extend(extract_all_text(item))
            
    return results
```

#### 场景 2：RAG（检索增强生成）中的本地知识库递归文件扫描

构建向量数据库（Vector DB）前，需要递归扫描某个文件夹下的所有子文件夹，把 Markdown 或 PDF 文件全部找出来：

```
import os

def get_all_md_files(dir_path):
    """递归扫描知识库文件夹中的所有 .md 文件"""
    md_files = []
    for item in os.listdir(dir_path):
        full_path = os.path.join(dir_path, item)
        if os.path.isdir(full_path):
            # 是文件夹，递归调用
            md_files.extend(get_all_md_files(full_path))
        elif full_path.endswith('.md'):
            # 是 md 文件，记录路径
            md_files.append(full_path)
    return md_files
```

#### 场景 3：AI Agent 自动多轮推理与反思（Loop & Max Depth 防御）

在 LangChain 或 LangGraph 中构建 ReAct 模式的 Agent 时，Agent 思考 -> 调用工具 -> 再次思考的过程本质上是一个递归/循环推演过程。为了防止 Agent 死循环，必须模仿递归终止条件设置 `max_iterations` ：

```
def run_agent_step(5
):
    """ Agent 递归推理步骤，带最大递归深度防护 """

    if depth >= max_depth:
        return "已达到最大思考深度，未能完成最终推理。"
        
    response = call_llm(query, history)

```
